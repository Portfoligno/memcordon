# Sealed provider protocol v1

This is a private local protocol. It is not a stable caller configuration API.

Each frame starts with a 72-byte header: big-endian protocol version (`u16`), message kind (`u16`), total frame length (`u32`), 16-byte request nonce, 16-byte attempt id, and the 32-byte SHA-256 digest of the payload. The remaining bytes are a counted payload. Total length is checked before allocation and is limited to 1 MiB. A digest mismatch rejects the frame before payload interpretation. Transport-derived peer identity and the request nonce provide authentication and replay binding; the digest is an integrity check, not a substitute for peer authentication.

Client kinds are `Probe`, `Launch`, `Cancel`, and `Query`. Provider kinds are `ProbeReceipt`, `LaunchPrepared`, `Authorized`, `Progress`, `Terminal`, and `Rejected`. Unknown versions and kinds are rejected; there is no legacy-parser fallback.

One authenticated request owns one connection. Launch payloads encode the native program, native argument sequence, environment entries, policy, absolute deadline, stream disposition, and descriptor inventory as separately counted values. They never encode a command line or a shell expression. Unix descriptors are transferred out of band and their exact count and purpose must match the payload. Windows stream relays are provider-created and no arbitrary caller handle is accepted.

An `Authorized` receipt is valid only after provider identity, guardian readiness, creation-time boundary assignment, independent assignment readback, inherited-resource verification, spawn-error reporting, and front-end-loss authority are established while the target remains gated or suspended. On Linux, the verified fd 3 control socket is bidirectional and close-on-exec. The target sends one fixed armed record immediately before native `exec`; close-on-exec EOF then proves successful image replacement, while a failed `exec` sends one fixed, versioned record containing the target-exec phase, an errno-derived class, and the native errno. Missing, malformed, duplicate, trailing, unclassified, or class/errno-inconsistent records fail closed. A `Terminal` receipt carries the resulting `exec-status`, optional native OS code, and positive spawn-error-path proof in addition to child status. Child exits 126 and 127 remain ordinary exits when `exec-status=success`; they are never inferred to be spawn failures from the exit number. A `Terminal` receipt is valid only after direct-target accounting, workload emptiness, helper reaping, and irreversible boundary retirement.

A `Rejected` payload is a versioned, bounded typed receipt rather than free-form text. It carries a stable provider code, the failed boundary phase, target-created and target-released facts, and restart-safety/retirement evidence. Its frame nonce and attempt id must match the request, and its payload digest must verify before decoding. Unknown fields, versions, contradictory cleanup claims, oversized details, or incomplete retirement claims are protocol failures. The provider journals a bounded non-secret event containing the attempt id, code, phase, authorization state, and cleanup result. A terminal exec failure likewise journals only its attempt id, target-exec class/native OS code, release state, and cleanup/retirement facts; it never journals argv, environment values, or descriptor contents.
